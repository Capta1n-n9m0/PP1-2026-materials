## Course Description

- **Prerequisites:** none. The course starts from the beginning: no programming experience is expected.

- **Technology requirements**
  - Bring your laptop to every class. You will be asked to write and run code during the class. Quizzes and exams are written on paper, without a laptop.
  - **Editor.** We recommend **Visual Studio Code** with the **C/C++ extension**. It is free and it works the same on Windows, macOS and Linux. You may use another editor if you prefer one.
  - **Compiler.** You may use **any C compiler** that accepts standard C. Your programs must compile and run without changes to the code. The course supports these:
    - **Linux:** GCC or Clang, installed with your distribution's package manager (for example `sudo apt install build-essential` on Ubuntu).
    - **macOS:** Clang, installed by running `xcode-select --install` in the Terminal.
    - **Windows, easiest:** **MinGW-w64 GCC** through the course's one-click installer `install-gcc-user.bat`. This is the option we support best.
    - **Windows, other ways:** **WSL** (Windows Subsystem for Linux), then GCC inside it as on Linux; or **MSVC**, the Microsoft C/C++ compiler (`cl.exe`), installed with **Visual Studio Community** or the **Build Tools for Visual Studio** and used from the Developer Command Prompt or from VS Code.
    - **Any platform, nothing to install:** **CoCalc** at https://cocalc.ai/, which runs in your browser.
  - **Git** is useful but not required.
  - Step-by-step instructions for each of these, with the exact commands and buttons, are in **"Setting up a C compiler"** on Blackboard. Follow that guide first; bring any problem to the forum.

- **Overview of the course:** this is a first course in programming, taught in the C language. It starts from the first program and builds up one idea at a time. **Part I** (before the midterm) covers the core of the language: variables, input and output, decisions, loops, functions and recursion, arrays, strings and two-dimensional arrays. **Part II** (after the midterm) looks under the surface: memory and pointers, command-line arguments, structures, enumerations and unions, dynamic memory, files, and searching and sorting. Every idea is shown on small programs that are written and run in class, and the code of every class is posted so that students can run it and change it themselves. Three programming projects apply the ideas to larger problems.

- **Student learning objectives:** after this course, students are expected to be able to:
  1. Write, compile, run, test and debug C programs from the command line.
  2. Use variables, the fundamental data types, input and output, decisions and loops.
  3. Decompose a larger problem into functions, and explain variable scope, call-by-value and recursion.
  4. Work with arrays, strings and multidimensional arrays.
  5. Use pointers, structures and dynamic memory allocation.
  6. Read, write and process files.
  7. Apply basic searching and sorting techniques, and analyze a program to predict what it does.

- **Methods of instruction:** two 75-minute classes per week. The class will be taught through lectures, including discussions around class examples and course homework. Discussions based on student contributions add a vital and dynamic element to the class. Students are expected to come to the class with comments or questions from the course readings. Eight short in-class quizzes check understanding as the course goes along. After every class a short online knowledge check opens on Blackboard, so that you can test yourself on that class's material at no cost to your grade.

- **Workload:** It is estimated that the students will need to spend 3-4 hours studying and preparation for the classes every week. Estimated amount of time to spend on course homework is additional 3-4 hours per week.

## Requirements

- **Quizzes (15%):** Eight short quizzes will be conducted throughout the semester, usually on Fridays; the Schedule below gives their dates. Each quiz will contain only one or two short questions and will focus on fundamental concepts recently covered in class. The quizzes are not intended to be difficult; their purpose is to encourage continuous study and verify students' understanding of the basic programming concepts. **Only the best six quiz grades will be included in the final grade.** Therefore, no make-up quizzes will be provided. The number of quizzes was changed from six (best five) to eight (best six) by a vote of the students of this section, held on 20–24 September 2026.

- **Knowledge checks (0%):** after every class a short online knowledge check opens on Blackboard: about 6 multiple-choice questions on that class's material, drawn from a small pool, so the same question may come up again in another attempt. Each check stays open for **three weeks**. You have **three attempts** and the best one is kept. The checks carry **no grade weight** and **cannot lower your mark**. They exist so that you can find out what you did not understand while there is still time to ask. Each check you complete earns a Blackboard badge. They are the best preparation for the quizzes, which cover the same material without a laptop. Students who complete every check on time may receive small bonuses at the instructors' discretion.

- **Programming projects (35%: 10%, 10% and 15%):** Students will complete three programming projects during the semester. The projects will require students to apply the programming concepts learned in class to larger and more practical problems. Projects will gradually increase in complexity as new topics are introduced. Each student is responsible for understanding all parts of the code submitted as part of a project. After submission, students may be asked by the Teaching Assistant to explain selected parts of their implementation, describe how particular functions or algorithms work, or make a small modification to their program. This verification is considered part of the project assessment. A student who is unable to demonstrate sufficient understanding of the submitted work may receive a reduced project grade.

- **Midterm exam (20%):** on **Friday 30 October 2026**, in the time of class 16; the room will be announced. It covers classes 1–14. The midterm examination will be conducted in a paper-based format and will assess the topics covered during the first part of the semester. Questions may include conceptual questions, code tracing, predicting program output, identifying and correcting errors, completing incomplete code, and writing short C programs or functions.

- **Final exam (30%):** in the final exam period, 22 December 2026 to 6 January 2027 (date set by the Registrar). The final examination will also be paper-based and will be cumulative, with greater emphasis on the topics covered during the second half of the course. Like the midterm, students may be asked to analyze C code, determine program output, identify errors, explain programming concepts, and write or complete short programs and functions. The final examination is intended to evaluate each student's individual understanding of the programming principles covered throughout the course.
